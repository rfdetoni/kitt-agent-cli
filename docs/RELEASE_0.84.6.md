# K.I.T.T. Agent CLI 0.84.6 — complete Goals/TaskPlan verification separation

## Remaining root-cause edge after 0.84.5

Agent 0.84.5 prevented the generic TaskPlan completion gate from rejecting a GOAL-owned turn when that turn had no TaskPlan. During final review, the same turn was still receiving a trusted `host-execution-state` segment generated by `TaskPlanCoordinator.context(...)`.

After a workspace mutation that segment advertised `task_plan: null` together with an OPEN mutation-verification obligation and a required next action to run registered verification. That contradicted the Goals contract prompt, which correctly delegates authoritative checks to `GoalStepVerifier` after the turn returns.

## Fix

For GOAL-owned turns with no nested TaskPlan, `TurnToolLoopMixin` now leaves the original typed context envelope unchanged instead of attaching TaskPlan host state. The same fail-closed predicate added in 0.84.5 owns both decisions:

- no nested TaskPlan: outer Goals verifier owns completion and TaskPlan host context is omitted;
- actual TaskPlan present: TaskPlan host context and completion gate remain active;
- non-GOAL turns: existing behavior remains active.

No execution budget was raised. No Protocol or Reverse Proxy contract changed.

## Verification

The predicate remains covered for GOAL/no-plan, USER/no-plan and GOAL/real-plan cases. PR CI additionally compiles and exercises the release-critical agent contracts.
